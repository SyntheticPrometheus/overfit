# Audience panel — first measured run, 2026-11-25

Two blind A/B panels, four raters each, same four personas, same build pair,
counterbalanced (pack1/pack3: live=A; pack2/pack4: live=B). The only difference
between the two runs is the transcript: pack1/pack2 print `You: …` action lines,
pack3/pack4 print the screen only (`--narrative off`).

| panel | cue | pref live | live mean | dead mean | gap | ENT | verdict |
|---|---|---|---|---|---|---|---|
| pack1+2 | actions shown | 4/4 | 3.75 | 2.63 | +1.13 | 0.281 | VALID |
| pack3+4 | screen only | 4/4 | 3.78 | 2.83 | +0.95 | 0.237 | VALID |

Reading:

- The panel separates the build from the choice-poor control **without** being told
  which is which, and it does so in both presentation modes. Deleting the action
  narrative costs 16% of the gap (1.13 → 0.95), so most of the signal is in the
  screen — costs, the `HARVEST ready for +N` line, the owned-tree list — not in the
  sentence "the game Harvested for you". That was the strongest objection to the
  instrument and it is now a measured number rather than a worry.
- Every rater's `wanted` line landed on a real defect, and two are already known
  from the instruments: at `hold 5` the tree is wiped every ~40 s so the owned list
  never takes a shape (casual: "wanted the trees I already grew to still be there");
  and the Harvest threshold recedes faster than income (veteran: "next Harvest
  6.10M … 38.1M"). The third is new: the screen never shows **what a Harvest is
  worth** next to its threshold, so the choice is not computable from the page
  (optimizer, minute 4). That is a UI change `fun.mjs` cannot ask for.
- Minute 10 was rated dead air in the live build by at least one rater running both
  arms — a concrete, addressable minute, not a vibe.

Commands: `node design/audience.mjs score design/audience/pack1/panel-*.json
design/audience/pack2/panel-*.json --check` (and pack3/pack4) — both exit 0;
`node design/audience.mjs selftest` — the gate rejects a 5/5 yes-man panel.
